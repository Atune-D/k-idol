## 3. 新电脑上的环境准备（Mac）

1. 安装 Git、Claude、Roblox Studio、Rokit（工具版本管理器）。
2. 拉取代码后，在项目文件夹里运行 `rokit install`，它会按 `rokit.toml` 装好同样版本的 Rojo、Lune、StyLua、selene。
3. 运行下面四条命令，都应成功：

   | 用途 | 命令 | 预期 |
   |---|---|---|
   | 全部单元测试 | `lune run tests/RunAllTests.luau` | 最后一行 `22 spec files, 266 tests: 266 passed, 0 failed, 0 spec file problems` |
   | 代码检查 | `selene src tests tools` | 0 errors, 0 warnings, 0 parse errors |
   | 格式检查 | `stylua --check src tests tools` | 无输出 |
   | 构建 | `mkdir -p build && rojo build default.project.json -o build/idolgrow.rbxlx` | Built project |

4. 连接 Roblox Studio（让 AI 能在 Studio 里试玩、读报错、截图）：
   - Studio 里：Assistant → … → Manage MCP Servers → 打开 Enable Studio as MCP server。
   - 项目文件夹里运行：`claude mcp add --transport stdio Roblox_Studio -- /Applications/RobloxStudio.app/Contents/MacOS/StudioMCP`
   - 重启 Claude。
   - ⚠️ 同一面板里的 Data access 开关打开后，Studio 会往 Claude 的全局设置里加自动上报的钩子，对所有项目的对话生效。是否打开由负责人决定。

## 7. 踩过的坑

- **测试工具会卡死。** 一个模块加载失败后，如果两个测试文件都加载它，Lune 0.11.1 会永远等下去。现在测试入口会先检查所有文件的语法，有错立即退出。模块在加载时报错（非语法错误）的情况会被正常报告，不会卡死。
- **杀进程要杀整组。** 路径上的 `lune` 是 Rokit 的转发程序，真正的 Lune 是它的子进程。只杀前者，后者会留下来继续占着。带超时运行时要用独立进程组并整组终止。
- **不要让两个子代理同时在同一个文件夹里做"改坏代码"的检查。** 一个改坏文件的瞬间，另一个跑测试就会看到莫名的失败。第二批就这样互相干扰过。要么错开，要么各用独立的工作副本。
- **禁止子代理用 `pkill` 这类按名字杀进程的命令。** 它会误杀别的子代理的测试。

## 8. 子代理留下的待定事项

这些是它们按最保守理解做出的选择，开发文档没有明确规定。接手后要么认可并写进开发文档，要么让负责人定。

| 事项 | 子代理的做法 |
|---|---|
| 读取存档算不算一次"保存开始" | 算。所以玩家刚进游戏就拿到的奖励，最多要等 10 秒才开始保存 |
| 保存进行中发生的外观改动 | 不触发补存，由下一次定时保存或最终保存写入 |
| 最终保存的重试 | 首次加 5 次重试共 6 次，间隔 1 秒（间隔是子代理自定的） |
| 每日进度的重置 | 只在读取存档时做。玩家在线跨天的情况留给第二阶段的每日模块 |
| 入门舞蹈的编号 | 叫 `starter_groove`、`starter_bounce`、`starter_sway`。开发文档的例子里写的是 `starter_wave` |
| 评分里的小数 | 主题分和完整度分不取整（如 33.33…），显示时再取整；总分向下取整 |
| 已存造型里"可用但与其他物品冲突"的物品 | 穿戴时跳过，存档里保留，单独报告 |
| 物品清单表格 | `isEnabled` 不分大小写；`marketplaceItemKind` 必须严格是 `Asset` 或 `Bundle`；不认识的列会被拒绝 |
