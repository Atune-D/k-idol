# 项目文档

## 两级文档体系

| 层级 | 位置 | 存什么 |
|---|---|---|
| 组织级 | 仓库群根目录 `docs/` | 涉及 ≥2 个仓库或生产基础设施的文档 |
| 仓库级 | `<repo>/docs/` | 只涉及该仓库代码的文档 |

**分类判据**：文档改动是否会因某一个仓库的代码变更而失效——是 → 仓库级；否 → 组织级。
单仓库项目只用一层即可。

## 目录

| 目录 | 用途 |
|---|---|
| `tasks/` | **全局任务管理系统**（先看这个）：`active.md` 唯一优先级视图 + `icebox.md` + `completed.md` |
| `plans/` | 进行中的改造计划，按 `MMDD-<主题>` 建目录；模板见 `plans/_templates/` |
| `specs/` | 技术规格与机制定稿（"系统怎么工作"） |
| `runbook/` | 部署手册、回滚预案、事故复盘（"怎么部署 / 怎么回滚"） |
| `infra/` | 基础设施登记册（"什么跑在哪 / 谁负责什么"） |
| `adr/` | 架构决策记录 |
| `project-log/` | 按月项目演进日志（发生过的事：事故、决策、里程碑） |
| `archive/` | 被替代的历史文档 |

`infra/` 与 `runbook/` 的分工：**infra 答"什么跑在哪"，runbook 答"怎么部署/回滚"。**

## 文档职责边界

- **本目录**：当前实现、准确命令、项目专属架构和 runbook。
- **`~/.claude/practices/`**：跨项目可复用的原因、规则、边界和验证方法。

同一内容不得在两处维护全文副本——用链接，并明确哪一份是 SSOT。
