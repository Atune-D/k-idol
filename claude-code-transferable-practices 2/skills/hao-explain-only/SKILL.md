# hao-explain-only

在对话里把一个系统机制讲到用户完全理解为止。**不写入任何文档**——需要落盘时用 `/hao-explain-to-doc`。

## 为什么有这个 skill

用户是产品设计出身（非科班工程师），不是科班工程师。抽象描述（"outbox 模式"、"幂等消费"）对他是噪音，**具体的数据行变化**才是信号。他反复要求的形态是：ASCII 流程图 + 真实字段名的示例数据表 + 逐步走一遍。本 skill 把这个形态固化下来。

## 解释前：先核实，不许编

解释必须基于真实代码。动笔前先读相关代码/migration/config，核实：表名、字段名、流程顺序、触发条件。字段名写错一个，整个解释的可信度归零。如果用户在上下文里贴过真实数据行，优先用它做示例，而不是编造。

## 解释内容规范（canonical——hao-explain-to-doc 引用本节）

按以下结构输出，可按对象复杂度裁剪，但 2、3、4 是灵魂，不可省：

### 1. 一句话定位
这是什么、解决什么问题、没有它会怎样。大白话。技术术语首次出现必须用一句话解释（例如："outbox（发件箱表：先把要做的事写进自己数据库，再由后台慢慢搬运，防止跨系统丢消息）"）。

### 2. ASCII 流程图
画出数据/控制流。要求：

- 箭头上标注**触发条件和时机**（谁触发、同步还是异步、多久跑一次），不要只画框和线。
- 宽度控制在 ~80 列以内，防止换行后图形碎掉。
- 分支/失败路径也要画（成功往哪走、失败往哪走）。

```
顾客支付成功
     │ (第三方平台回调，实时)
     ▼
POST /api/webhooks/wxpay/notify/{code}
     │ 验签通过
     ▼
customer_pays.paid_at 写入 ──────────► order_confirmation_runs 插入一行
                                          │ (queue job, 异步, 秒级)
                                          ▼
                                     逐步执行 pipeline_steps
                                          │ 某步失败？
                                          ▼
                              sweeper (cron, 每5分钟) 扫描未完成 run 重试
```

### 3. 示例数据表
用示例行展示关键表在流程各阶段的**前后变化**。要求：

- 表头用真实字段名（核实过的），不要用中文意译的假字段。
- 给出 before / after 对比，或按时间线给多个快照。
- 数值要自洽（金额、时间戳、外键 id 前后要对得上，能互相引用）。

```
执行前 orders：
| id      | order_status | confirm_date | order_income |
| 4095784 | created      | NULL         | 0.00         |

执行后 orders：
| id      | order_status | confirm_date | order_income |
| 4095784 | confirmed    | 2026-08-06   | 248.00       |

同时 order_confirmation_runs 新增：
| id | order_id | pipeline_status | attempt_count |
| 3  | 4095784  | completed       | 0             |
```

### 4. 以一个具体例子走完整个流程
选一个具体场景（优先用用户刚提到的真实订单/数据），按时间顺序走一遍：每一步发生了什么、哪张表哪一行变了、谁触发的。让流程图和数据表在叙事里串起来。

### 5. 边界与常见误解
- 什么情况下**不会**发生 / 会失败 / 会跳过。
- 与相似机制的区别（比如这张表和另一张长得像的表，各自的生态位）。
- 用户最可能误解的点，主动澄清。

### 6. 讲问题/风险时的展开方式
凡是涉及"这里有个问题/风险"，必须用「是什么 → 为什么要改 → 不改会怎样」三段大白话展开，不许压缩成一句行话。

## 输出纪律

- 只在对话里输出，**不创建、不修改任何文件**。
- 解释完后如果用户说"写进文档"，切换到 `/hao-explain-to-doc` 的流程（复用你已经写好的内容）。
