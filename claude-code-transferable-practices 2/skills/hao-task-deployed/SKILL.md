# 部署后任务同步流程

用户告知部署完成后，**不需要用户追问**，按以下顺序自动执行。所有输出用中文。

## 第 1 步：锁定部署对象

从用户消息确认：哪个仓库、哪个 branch、哪个 commit。缺失且无法从上下文推断时，先问清再继续。

## 第 2 步：读取任务现状

1. `docs/tasks/active.md`（全局视图）——注意可能被其他会话更新过，**先读再改，保留他人改动**。（Icebox 已拆分为 `tasks/icebox.md` 的项目，仅第 4 步收编新任务时才需要碰它。）
2. 从对应 initiative 的"详情"列进入其执行板 / plan 文档（如 T-1 → `docs/plans/<initiative>/<initiative>-backlog.md`）。

## 第 3 步：更新部署相关状态（顺序固定）

1. **执行板**：把本次部署对应的任务行改为 Done ✅（记日期），被解锁的后继任务改为 Todo；刷新"当前位置"。
2. **`docs/tasks/active.md`**：更新 initiative 行的状态与"当前步"。语义提醒：**部署 ≠ 完成**——上线后进入验证/观察期的用 `Deployed` 状态，验证通过才是 Done。
3. **`docs/tasks/completed.md`**：追加一行（日期 · ID · 名称 · 结果一句话）。
4. 相关 plan 文档中有对应 checklist 的，同步打 ✅。

## 第 4 步：收编 docs/plans/ 里的新增/修改计划

用户会不定期往 `docs/plans/` 写入新计划，但不会立即决定执行时机。每次触发本流程时顺带扫描收编：

1. **检测**（docs/ 是独立 git 仓库，用 git 做增量检测）：
   - `git -C docs status --short plans/` —— 未提交的新增/修改；
   - 交叉核对：`plans/` 下每个 `.md` 都应被 `tasks/` 下任一文件（active / icebox / completed）、某个执行板或 `archive/` 引用；
     无人引用的 = 疑似孤儿。⚠️ 防误报：引用可能不带 `.md` 后缀（正文提及文件名）——判孤儿前先用**无扩展名基名**再 grep 一次，仍无引用才算。
     孤儿的处置（归档 / 立项）列给用户拍板，**不自动归档**。
2. **收编规则**：
   - 新计划 → 新建 DR 行（**ID = active + icebox + completed 全库最大序号 +1**，永不复用），状态 `Planned`（plan 已就绪）；
     **分区默认进 Icebox**（用户未承诺执行时机，不允许替用户排期；Icebox 若已拆分为独立 `tasks/icebox.md` 则写入该文件——以项目 tasks/README.md 的文件结构为准），依赖列如实填写；
   - 已有 DR 条目对应的计划被修改 → 检查修改是否影响该行的状态/依赖/当前步描述，按需同步；
   - 在回复中**明确列出收编结果**，请用户决定是否调整分区（升 Later/Next 由用户拍板）。
3. 收编的文件与任务变更一起进入第 5 步的 commit。

## 第 5 步：提交

在 `docs/` 仓库（独立 git 仓库）提交：**显式 `git add <本流程改动的具体文件>`，禁止裸 `add -A`**——
其他会话可能有未提交的 WIP（audits/、research/ 等），不许卷进本次 commit。
message 说明部署内容、状态变化与收编的计划。（遵守全局规则：不加 Co-Authored-By trailer。）

## 第 6 步：分析并输出下一步建议

> 本步的判据与只读命令 `/hao-task-next` **同源**：`hao-task-next` 是"不改文件、纯给建议"的独立版；
> 本 skill 是"先写同步（第 1–5 步）再给同一套建议"的部署后完整版。两者判据保持一致。

按此优先级推理，并在回复中给出明确建议 + 理由：

1. **部署后验证永远优先于新工作**——本次部署有无对应的验证任务？有则列出具体验证命令/清单。
2. 本次部署解锁了哪些依赖（执行板依赖列里划掉的前置）？其中哪个是关键路径？
3. 有无被激活的红线/观察期（如"某索引在验证前严禁删除"、"慢日志观察至某日"）？必须显式重申。
4. 结合 `active.md` 的 Now/Next 排序，给出**一个**最优先动作（可附并行项），不要罗列全部可能。

## 注意事项

- 其他会话可能并行更新过任务文件：Edit 前必须先 Read 最新内容，只改本次相关的行。
- 如果部署的内容在任务系统里找不到对应条目，先补建条目（进对应执行板或 active.md），再走流程。
