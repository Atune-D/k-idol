# hao-task-next

分析当前项目状态，给出**一个**最优先动作 + 理由。**只读：绝不改文件、绝不 commit、绝不执行任务。**

## 前提：定位任务系统

从当前工作目录向上查找 `docs/tasks/active.md` + `README.md`。找不到 → 告知未采用 `docs/tasks` 系统，结束。

## 执行步骤

1. **读任务现状**：`docs/tasks/active.md`（尤其 **Now 区**）+ 相关 initiative"详情"列指向的执行板/plan（只读扫当前步）。Icebox（含拆分后的 `icebox.md`）是未承诺条目，**不参与"下一步"判断，无需读取**。
2. **了解代码/部署状态（只读）**：
   - `git log --oneline -10`、`git status`：最近做了什么、有无未提交/未部署改动。
   - 执行板/plan 里的"当前步""待部署""观察期"。
3. **按此优先级推理（与 hao-task-deployed 第 6 步同源）**：
   1. **验证/观察永远优先于新工作**：有没有已部署但未验证的项（`Deployed` ≠ `Done`）？有则先列具体验证命令/清单。
   2. **红线 / 观察期**：有没有被激活的禁令（如"某索引验证前严禁删除""慢日志观察至某日"）？必须显式重申。
   3. **解锁的依赖**：最近完成/部署解锁了哪些后继？哪个在关键路径。
   4. **Now 区行序**：结合 `active.md` 的 Now/Next 顺序（=优先级）给建议。
   5. 上下文热度、完成难度作为次要维度。
4. 输出**一个**最优先动作（可附一个并行项），说清理由；不罗列全部可能。

## 输出格式

```
## 建议优先处理
**[具体动作]**（来自 T-x / 执行板 SB-x）
理由：[2-3 句：依赖 / 风险 / 验证优先 / 热度]

## 需重申的红线 · 观察期
- ...（如有，无则省略本节）

## 其他参考顺序
1. [任务] — 一句话理由
2. ...
---
*仅建议，未执行任何操作。要落地某项请单独动手。*
```

## 严格限制

- **只读**：不改任何文件、不 commit、不执行任务。
- 若发现任务文件与现实不符（如已部署但状态没更新）：只**指出**并建议用 `/hao-task-deployed`（或手动）同步，不擅自改。
- 建议要具体、给理由，不要只说"重要""紧急"。
- 全程用中文。
