## 硬约束（按项目实际情况改写，删掉不适用的）

- **【最高优先级】未经明确允许不得登录生产环境**，即使操作是只读的。涉及生产的排查请求，默认输出「目的 → 可直接复制的命令 → 每条命令看什么、什么结果算正常/异常」，由我自己执行并回贴结果。
- **【最高优先级】只允许操作 `<测试数据库名>`。** 其他数据库（本地开发库、生产库）一律不得写入、修改或删除。
- **破坏性操作一律先确认**：删除文件/目录、移动文件、停服务、修改系统配置、`git push --force`。不确定是否安全就先问。
- **git 写操作必须显式 `git -C <绝对路径>`**，禁止裸 `git add -A`（本工作区可能有未提交的 WIP）。提交后核对 `git show --stat`。
- **每次开发新功能后自动补充对应测试**，不需要我提醒。
- **汇报测试结果必须写明类型、目录、数量，并说明没跑什么。** 禁用「全量回归」这类模糊表述。

## 工作方式

- **接了活自主连续推进**，不要每完成一个小增量就问「要我继续吗」。只在这四种情况停下：涉及产品取舍 / 涉及不可逆动作 / 两个方案代价相当且我有偏好 / 发现的事实与任务前提矛盾。
- **提问必带推荐答案**：「建议 A，因为 X；选 B 的话代价是 Y」，而不是「A 还是 B？」
- **提任务编号必须同时一句话说明它指什么。**
- 开工前先读 `docs/tasks/active.md` 的 Now 区。
