# 任务管理系统（文件承载、Linear 风格）

## 三个工作文件

| 文件 | 内容 | 更新方式 |
|---|---|---|
| `active.md` | **唯一的优先级视图**：已承诺的任务，按 Now / Next / Later 分区，区内自上而下即优先级 | 随时改：改状态、改排序、增删行 |
| `icebox.md` | 想法池：未承诺执行时机的条目 | 新想法默认落这里；升区时整行移回 `active.md` |
| `completed.md` | 终态归档（Done / Dropped），带完成日期和结果一句话 | 只追加，不修改 |

**为什么不按状态拆文件**（backlog / doing / done 各一个）：优先级排序是**跨状态**的全局判断，拆开就失去了"一眼看清下一步做什么"的能力。状态是行内字段，文件只区分"还要看 / 不用再看"。

## 两层结构

- **Initiative（战役）**：跨多周、有独立 plan 文档的大工程。在 `active.md` 里**只占一行**，细节全部在它的 plan / 执行板文档里（引用链接）。本系统只管"多个战役之间怎么排优先级"，不复制战役内部的步骤。
- **Task（独立任务）**：不隶属任何战役的一次性事项，同样一行。

## 字段与取值

| 字段 | 取值 |
|---|---|
| ID | `T-<序号>`，全局递增、**永不复用**（战役内部细节任务用各自的编号，如 `SB-x`）。可按项目改前缀 |
| 状态 | `Backlog`（想做，未定方案）→ `Planned`（plan 文档已就绪）→ `In Progress` → **`Deployed`（已上线，观察/修 bug 期——已部署 ≠ 完成）** → `Done` / `Dropped` |
| 负责人 | 人名 / `Claude` / `双方` |
| 依赖 | 阻塞本任务的 `T-x` 或外部条件 |
| 详情 | 指向 plan 文档 / 执行板的相对链接（**本系统不写细节**） |

## 分区语义（优先级的第一维度）

- **Now**：当前唯一或少数几个主攻方向（**≤3 行，强制聚焦**）
- **Next**：Now 完成后立即接上的
- **Later**：确定要做、但不急
- **Icebox**（独立文件 `icebox.md`）：想法阶段，可能永远不做

区内**行的先后顺序就是优先级**，调整优先级 = 移动行。

## 工作流约定（对 AI 同样生效）

1. 任何相关会话开工前先读 `active.md` 的 **Now 区**。
2. 推进/完成任何事项后立即更新对应行；进终态的行**剪切**到 `completed.md` 并补一句结果。
3. 新想法一律先进 `icebox.md`，想清楚了再升区（整行移回 `active.md`），**不允许直接插进 Now**。
4. 每次变更随手 `git commit`（历史即审计日志）。

## 配套 skill

| 命令 | 作用 | 是否写文件 |
|---|---|---|
| `/hao-task-add <任务>` | 分析后合理并入任务板（默认进 Icebox） | 写 |
| `/hao-task-list` | 展示优先级视图 | **只读** |
| `/hao-task-next` | 给出一个最优先动作 + 理由 | **只读** |
| `/hao-task-deployed` | 部署后同步状态、收编新 plan、commit | 写 |
